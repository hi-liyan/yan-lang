# M0：语言示例评审

状态：进行中
范围：在继续实现编译器前，确认 Yan 的表层语法与核心使用体验

## 目标

通过 `examples/language-design/` 中可直接阅读的 Yan 程序，确认这门语言是否符合“Java 的可读性、Kotlin 的现代简洁性、Yan 的严格边界”这一方向。

M0 的产物是被确认的语言示例，而不是可运行的编译器功能。`yanc` 当前只能进行最小词法分析，不应被用于判定这些提案的语法合法性。

## 评审原则

- 每个文件只引入少量新概念，避免示例同时掩盖多个语法决策。
- 示例优先表达个人开发者最常见的应用代码，而非编译器实现便利性。
- Web、CLI 等平台能力必须以 import 的库形式出现，不能演变为语言关键字。
- 任何难以读懂、容易让 AI 生成多种风格、或需要大量例外规则的写法都应在此阶段删除或重写。

## 验收问题

审核每个示例时确认：

1. 第一次阅读时，数据、控制流和副作用是否清晰？
2. 是否存在 Java/Kotlin 已知的冗余或魔法，需要主动避免？
3. 是否能用更少的语言概念表达同一需求？
4. 是否会诱导 AI 生成继承层、动态类型、隐式转换或隐藏依赖？
5. 语法是否适合在未来稳定地格式化、解析和诊断？

## 完成条件

- 用户逐个确认、修改或拒绝所有核心示例。
- 确认关键字、单文件模块规则、类型标注、结构体构造、错误处理、可选值和导入语法。
- 将已确认示例标记为 v0.1 语法样例。

完成前，禁止继续实现 parser、类型检查或代码生成。完成后进入 M2，并以确认的示例建立 parser 测试。
